# 8단계 출점 검토 워크플로

Phase 8은 기존 도메인 엔진을 프랜차이즈 점포개발 담당자의 한 작업 흐름으로 연결한다. 기본 진입점은 백초밥 명지점 테스터 샘플의 후보지 화면이며, 실행 시 전체 예시 분석을 자동 준비한다. 기존 도면 편집기 단독 진입은 `?workspace=space`로 유지한다. `#site`, `#space`, `#market`, `#demand`, `#operation`, `#scenario`, `#financial`, `#review`는 현재 단계를 표시하며 입력이나 분석 결과를 URL에 저장하지 않는다. 자동 준비가 완료되어도 사용자가 열어둔 단계나 hash를 바꾸지 않는다.

## 실행

프로젝트 폴더의 Windows PowerShell에서 다음 명령을 실행하고 `http://127.0.0.1:5173/`을 브라우저로 연다. `strictPort: true`이므로 5173이 사용 중이면 시작 오류를 표시한다. 이미 같은 프로젝트의 개발 서버가 실행 중이면 기존 주소를 사용한다. 다른 포트로 자동 이동하지 않는다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\start.ps1
```

이 스크립트는 `npm.cmd`와 Node.js를 확인하고 필요하면 `%USERPROFILE%\.local\node`의 portable runtime을 사용한다. 현재 프로세스에서만 PATH를 보완하고 종료 시 복원한다. `node_modules`가 없으면 `npm ci`를 실행한다. `-Task test`, `-Task build`, `-Task test:e2e`, `-Task preview` 및 뒤에 붙인 실행 인자를 지원한다. 빌드·개발 서버 시작만으로 GitHub Pages가 갱신되지는 않는다.

## 입력 없이 샘플 보기

첫 화면의 **샘플 영업 바로 보기**를 누른다. 준비 중에도 가상영업 화면으로 이동할 수 있다. 하나의 Worker가 Demo 상권 → 수요 → 반복 가상영업과 재생 기록 → 네 시나리오 → 전환율 민감도 → 재무를 계산한 뒤 결과를 함께 반영한다. 미리 적어둔 결과 숫자를 화면에 끼워 넣지 않는다. 완료 후 재생하거나 시나리오·수익성·출점검토를 바로 열 수 있으며, 초기 샘플에는 수동 입력이나 확인 체크가 필요하지 않다. 실패하면 오류와 **샘플 다시 계산**을 표시한다.

| 기본 후보지 정보 | 값과 출처 |
|---|---|
| 점포명 / 브랜드 | 백초밥 명지점 / 백초밥 · 사용자 제공 |
| 주소 | 부산광역시 강서구 명지국제2로 80 비주거시설동 1층 1-86, 1-87호 · 사용자 제공 |
| 입력 면적 | 94.44 m² · 사용자 제공 |
| 공간 모델 | 기존 공개 예시 도면, 형상 면적 약 159.9 m² · 명지점의 실측 도면 아님 |
| 상권·운영·가격·비용 | synthetic 자료와 수정 가능한 체험 가정 · 실제 점포 관측값 아님 |

94.44 m²와 도면 형상 면적은 각각 표시한다. 입력 면적에 맞춰 원본 형상이나 좌석 정원을 자동 축소하지 않으므로 분석 결과를 실제 명지점의 운영·매출로 해석하면 안 된다. 모든 필드는 수정 가능하다.

## 값을 바꾸며 단계별 사용

| 단계 | 사용자 작업 | 결과와 주의할 구분 |
|---|---|---|
| 01 후보지 | 미리 입력된 점포명·브랜드·주소·면적·메모 확인 또는 변경 | 주소는 후보지 식별 정보다. 실제 지역 데이터 조회나 지오코딩을 하지 않는다. 입력 면적은 도면 측정값을 바꾸지 않는다. |
| 02 공간설계 | 샘플은 `예시 공간으로 계속`, 변경 도면은 운영 역할·정원 확인 | 기존 PDF/JSON import·2D 편집·3D·undo·export를 재사용한다. 예시 설정을 사람이 확인한 사실로 기록하지 않는다. |
| 03 상권분석 | 자동 준비된 Demo 검토 또는 `상권 자료 다시 불러오기` | 평일·주말 시간대별 유동/생활인구와 주변 업종 예시를 표시한다. 공급자·기간·가상 자료 표시를 유지한다. |
| 04 수요가정 | 참여율·점포 선택·방문 전환과 배달 주문 가정, 수요 계산 | 상권 통행량을 홀 고객/시간으로 변환한다. 배달은 독립 주문/시간이며 홀에서 차감하지 않는다. |
| 05 가상영업 | 인력·주방·시간 가정 후 실행, 기록 재생 | 실제 배치 위에 테이블 점유·자원 사용·대기·배달 상태를 표시한다. 첫 실행 기록과 반복 평균은 다르다. |
| 06 시나리오 | 보수·기준·낙관·사용자 조건 비교, 1-way 민감도 | 같은 seed 목록에서 조건을 바꾼다. 방문 전환율·좌석 정원·주방 동시 조리·홀 객단가를 선택할 수 있다. |
| 07 수익성 | 객단가·월 영업일·비용·투자 가정 입력, 재계산 | 완료된 홀 고객과 배달 주문을 기준으로 월 손익·손익분기·단순 회수기간을 계산한다. |
| 08 출점검토 | 운영·재무·시나리오·민감도와 확인 사항 검토, JSON 저장 | 점수나 GO/NO-GO를 생성하지 않는다. 표시된 가정·실행 결과에서 확인 사항을 만든다. |

단계는 자유롭게 이동할 수 있지만 계산에 필요한 입력이 없으면 앞선 준비 단계를 안내한다. 공간설계는 단계 이동 중에도 같은 편집기 세션을 유지하므로 작업 중인 도면과 undo 기록을 잃지 않는다. 숨겨진 편집기의 단축키는 다른 화면 입력에 작용하지 않는다.

## 공간과 예시 가정 확인

기본 도면은 기존 공개 백초밥 샘플이다. 이 샘플만 `door-entry` 출입구, `range` 주방, `self-bar` 서비스 거점, 테이블당 4석을 예시로 지정한다. `sampleSpaceReady`는 이 예시를 체험할 수 있는 상태이고, 사람이 확인한 `spaceConfirmed`와 분리한다. 샘플 상태에서는 확인 체크박스 대신 **예시 공간 설정**과 **예시 공간으로 계속**을 표시한다. 실제 사용자 확인 상태를 자동으로 true로 만들지 않는다.

도면이나 운영 매핑을 편집하면 샘플 공간 준비 상태를 해제하고 실제 정원·역할 확인을 요구한다. 새 PDF/JSON을 불러오면 기존 매핑과 확인 상태도 비운다. 테이블별 정원과 zone 역할은 고급 공간 정보에서 수정한다.

초기 수요·운영·가격·비용도 보정되지 않은 예시다. `createWorkflowConfiguration`은 평일 11–21시, seed 1001부터 3회 반복, 독립 배달 3건/시간, 월 26일을 설정한다. 화면용 실행 서비스는 반복실험을 최대 10회로 제한한다. 월간 계산은 선택한 대표 요일의 관측 구간을 하루로 보고 `runToDayMultiplier=1`로 환산한다. 시간이나 요일을 바꾸었으면 수익성의 환산 근거를 확인한다. 다양한 요일을 함께 가중하는 도메인 API와 현재 단일 대표 요일 UI는 구분한다.

## 계산과 재생은 별개

운영·시나리오·민감도·재무 계산은 `analysis.worker.ts`의 Web Worker에서 기존 엔진의 공개 API로 실행한다. 화면의 재생 시간이나 브라우저 frame rate가 DES 이벤트를 진행시키지 않는다. 계산이 끝난 뒤 첫 번째 반복실험의 30초 간격 `SimulationFrame` 기록을 재생한다. 기본 10시간 관측은 시작·종료를 포함한 1,201개 기록이다.

기록에는 홀 고객과 배달 주문을 분리한 도착·완료·이탈·대기, 진행 중 일행/주문의 단계, 자원별 사용량과 실제 테이블 단위 배정이 담긴다. 화면은 선택 시각 이전의 최근 기록을 표시하며 중간 고객 움직임을 만들어 보간하지 않는다. 1×/5×/20×/120×/600× 속도·일시정지·처음부터·시각 탐색은 기록 조회만 바꾼다. 30초 사이의 짧은 상태는 화면에 나타나지 않을 수 있으나 전체 KPI는 모든 이벤트에서 계산된다. 보행 경로·이동거리·라이더는 구현하지 않았다.

## 조건 변경과 지난 결과

`workflowInputKeys`가 실제 입력 값을 기준으로 결과의 최신 여부를 판별한다. 주소/점포명 → 상권 → 수요 → 도면·운영 → 재무·비교의 의존 관계를 반영한다. 좌석·도면을 수정하면 공간 확인도 다시 필요하다. 비용만 바뀌면 완료된 운영 실행은 유지하고 재무·조건 비교를 다시 계산할 수 있다. 메모·브랜드 표기와 별도 참고 면적은 DES 입력을 바꾸지 않는다.

지난 결과는 조용히 새 조건의 결과로 바꾸지 않고 재계산 필요 상태를 표시한다. 지난 영업 기록은 원래 run snapshot의 도면·시각으로 재생한다. 입력을 바꾸거나 새 작업을 시작하면 진행 중 worker를 종료하고 이전 응답을 무시한다. 초기 샘플 계산 중 편집해도 늦게 온 초기 결과가 사용자 값이나 현재 단계를 덮어쓰지 않는다. 실패를 0 매출이나 성공 결과로 대체하지 않는다. 테스터 모드가 Demo를 자동 준비하는 것은 명시된 제품 동작이며 실제 API 실패를 가상 자료로 숨기는 fallback은 없다.

## 저장과 공개 범위

후보지·입력·계산 결과는 현재 브라우저 메모리에 있다. 새로고침이나 재접속은 백초밥 명지점 테스터 기본값과 새 계산으로 시작한다. 이전 편집 내용을 자동 복원하지 않으며 서버 저장, 프로젝트 목록·계정도 없다.

- 공간설계의 **JSON 저장**은 오버레이가 포함된 기존 FloorPlan 파일이다. **JSON 불러오기**로 공간 편집본을 다시 열 수 있다.
- 출점검토의 **검토 결과 저장**은 `store-review.json`이다. 후보지·입력 가정·출처·레이아웃·운영 집계·재무·시나리오별 적용 가정과 결과·민감도 변수와 기준값 및 지점별 결과를 내보낸다. 전체 run snapshot이나 재생 기록의 프로젝트 백업/복원 포맷은 아니다.
- 검토 자료 내보내기는 현재 운영·시나리오·재무가 준비되고 관련 결과가 최신일 때 가능하다. 민감도는 선택 사항이지만 실행 후 조건이 바뀌었다면 갱신해야 한다.
- 새 PDF/JSON은 브라우저에서 처리한다. 기존 공개 샘플은 배포 번들에 남는다. 이 단계는 접근 제어나 원본 도면의 비공개화를 추가하지 않는다.

Phase 8 작업은 로컬 구현·검증·문서화 범위이며 원격 푸시나 production 배포를 자동 수행하지 않는다. 검증 수치와 실행 기록은 [개발 계획](development-plan.md)에 별도로 기록한다.
