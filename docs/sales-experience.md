# 백초밥 영업용 검토 화면

사용자가 제공한 `C-Photo-View.jpg`를 원본 그대로 `public/baek-sushi-logo.jpg`에 배치했다. 백초밥 인장의 붉은색과 먹색, 따뜻한 바탕색을 공통으로 사용한다. 매출과 이익은 금색·녹색, 손실과 비용 차감은 붉은색으로 구분하되 숫자와 문구도 함께 표시한다.

## 구성 참고

- [Shopify의 분석 대시보드](https://help.shopify.com/en/manual/reports-and-analytics/shopify-reports/overview-dashboard/customizing-overview-dashboard): 주요 지표 카드와 구획별 정보 밀도.
- [LivePlan](https://www.liveplan.com/): 가정을 바꾸면 연결된 재무 결과가 함께 바뀌는 흐름.
- [Stripe Dashboard](https://stripe.com/payments/features): 핵심 지표를 먼저 보여주고 세부 보고서로 연결하는 구성.

외부 제품의 수치나 화면 자산을 가져오지 않았다. 기존 실제 계산 엔진과 사용자 제공 브랜드 자료를 새 레이아웃에 연결했다.

## 입력과 결과

마지막 단계는 **06 수익성 분석 → 07 시나리오 비교 → 08 출점검토**다. 수익성은 주요 입력과 KPI·비용·손익분기를 나란히 보여주며, 추가 비용과 투자 세부는 펼쳐서 확인한다. 시나리오 조작은 비교표 위에 놓이고 민감도는 별도 고급 영역에 있다. 좁은 화면에서는 세로로 재배치하며 큰 비교표만 내부 가로 스크롤을 사용한다.

입력 후 550ms에 `refresh` Worker를 실행한다. 입력 key가 같은 결과는 재사용하고 나머지는 실제 엔진에서 계산한다. 비용 변경은 운영 기록을 유지하지만 수익성·시나리오·민감도를 갱신한다. 변경 중 기존 결과임을 표시하고 이전 Worker의 늦은 응답을 무시한다. 유효하지 않은 입력은 실행을 보류하고, 실패한 요청은 같은 입력으로 무한 재시도하지 않는다. 새 공간이나 매핑은 확인 후 계산한다.

## 공유용 엑셀

출점검토에서 최신 결과를 `.xlsx` 제안서로 내려받는다. 브랜드 로고, 후보지 정보, 월 손익, 조건별 비교, 가정·출처를 인쇄 가능한 서식에 담는다. 브라우저에서 생성하므로 입력 내용을 외부 서버로 보내지 않는다. 수치형 셀에는 실제 계산값을 기록하며 사용자 문자열은 수식으로 실행하지 않는다.

이 보고서는 계산 시점의 제안 자료다. 엑셀의 가정 숫자를 고쳐도 웹의 시뮬레이션을 재실행하는 것은 아니다. 다시 계산하려면 웹에서 조건을 바꾸고 새 보고서를 다운로드한다. 예시 상권과 기존 예시 도면의 출처, 사용자 입력 면적 94.44 m²와 도면 면적의 차이도 유지한다.
